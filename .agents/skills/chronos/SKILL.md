# chronos — 1日の振り返り

1日の終わりに、その日に何をしたか・何に気づいたか・AI をどう使ったか・次に何をしたいかを1つずつ聞き、`logs/` に記録して push する。テーマ1つの振り返り（playground の report.md）とは別に、1日全体を見る。

段階ごとに、することが増える。段階の中身と上がるきっかけは、同じディレクトリの `stages.md` に書いてある。

## 1. 準備

1. `chronos.md` を読み、今の段階を知る
2. `stages.md` を読む。今の段階までの「毎回すること」と、次の段階の「上がるきっかけ」を使う
3. 今日の日付を `date '+%Y-%m-%d %H:%M'` で取る。0時〜4時のときは「昨日の振り返りとして記録しますか？」と聞き、そうなら前の日の日付を使う

## 2. playground を読む（読むだけ）

`~/playground/<YYYY>/<YYYYMM>/<YYYYMMDD>`（その日の日付ディレクトリ）の中のテーマのディレクトリを見て、`plan.md`・`report.md` を読む。各テーマのゴールと、終わったかどうかをつかむ。

- `~/playground` には何も書き込まない。ファイルを作る・直す・commit することもしない
- 日付ディレクトリがなければ、黙って次へ進む

## 3. 今の段階の「毎回すること」（問いの前の分）

`stages.md` で、今の段階までに「問いの前」と書いてあるものをする。段階0ではない。

## 4. 4つの問い

1問ずつ聞き、答えを受け取ってから次へ進む。

1. **今日やったこと**: 手順2で読んだものがあれば、「今日は〜をしましたね。合っていますか？」と確かめる形で聞く。なければ「今日は何をしましたか？」と聞く。「合っている」とだけ答えたら、下書きをそのまま記録に使う
2. **気づいたこと・詰まったこと・面白かったこと**
3. **AI の使い方**: 毎回、次の形のとおりに出す。問いの文 → 6つの選択肢（省かない）→ 予想、の順を変えない。選択肢を先に並べるのは、予想の理由を選択肢と見比べて確かめられるようにするため。予想は、1と2の答えのどこからそう思ったかを添え、記号だけでなく名前も書く。本人は、合っていればそのまま、違えば一言で直す

   ```
   今日の AI の使い方は、どれでしたか？（いくつでも）

   A. 初めての分野に挑戦した — AI のおかげで、知らない分野でもやりとげられた
   B. 学ぶ手伝い — 新しいことを学ぶ・練習するのを手伝ってもらった
   C. 相談相手 — 意見をもらった、考えを聞いてもらった
   D. 思い出す — 前に決めたことや経緯を、AI が覚えていて助かった
   E. 整理 — ばらばらなものを整理してもらった
   F. その他（自由に）

   1の「〜」から、B（学ぶ手伝い）だと思います。合っていますか？
   ```
4. **次にやってみたいこと・気になっていること**

## 5. 今の段階の「毎回すること」（問いの後の分）

`stages.md` で、今の段階までに「問いの後」と書いてあるものをする。段階0ではない。

## 6. 記録する

`logs/YYYY-MM-DD.md` に次の形で書き、中身を短く見せる。

```markdown
# YYYY-MM-DD

## 今日やったこと
<記録>

## 気づいたこと・詰まったこと
<記録>

## AI の使い方
- 種類: <A〜F、いくつでも>
- 一言: <あれば>

## 次にやってみたいこと
<記録>

## Chronos から一言
<今日の記録を見ての短い一言。段階1からは、くり返しに気づいたらここに書く>
```

- 本人が言ったことだけを書く。空いている項目を埋めるために話を作らない
- 書いたら、まだ commit せずに手順7へ進む

## 7. 段階を確かめる（commit の前に毎回）

記録を書いたら、commit する前に必ずこの手順をする。段階が上がると `chronos.md` などが変わり、それも同じ commit に入れるため。

`stages.md` の、次の段階の「上がるきっかけ」を、コマンドで確かめる（例: 段階1なら `ls logs/*.md | wc -l`）。結果は毎回、次の形で一言伝える。

- **満たしたとき**: 自動で上げる。`stages.md` のその段階の「上がるときにすること」をして、`chronos.md` の「今の段階」を書き換え、表に1行足す。そのうえで「段階1に上がりました。次から、前の記録からくり返しに気づけるようになります」のように、何ができるようになったかを知らせる
- **あと1つで満たすとき**: 「次の振り返りで段階1に上がります。前の記録から、くり返しに気づけるようになります」のように、上がると何ができるかを添える。「明日」とは言わない（毎日続けることを求めていないため）
- **それより前**: ゲージで伝える。1マスが1つ分で、埋まった分を ■、残りを □ にする（例: `段階1まで ■■■■□□□□□□ 4/10`、`段階2まで ■□□ 1/3`）
- 段階3になったら、ゲージは出さない（この先の段階は準備中のため）

## 8. 月の最終日なら、1か月を振り返る

その日が月の最終日なら、段階に関係なく、記録のあとに次をする。

1. その月の `logs/` を全部読み、`context/retrospectives/YYYY-MM.md` に書く。中身は、よく出たこと・AI の使い方の内訳（A〜F が何回ずつか）・次の月にやってみたいこと。記録が少なくても書く
2. その月のカレンダーを見せ、同じものを振り返りのファイルの先頭に入れる。記録した日を ■、記録しなかった日を □ にし、月曜始まりで7列に並べる

```
11月  23/30日
 月 火 水 木 金 土 日
                   ■
 ■  ■  □  ■  ■  ■  □
 □  ■  ■  ■  ■  ■  □
 ■  ■  ■  ■  ■  ■  □
 □  □  ■  ■  ■  ■  ■
 ■
```

3. カレンダーを見て、曜日のくせ（例: 日曜がよく抜ける）があれば一言伝える

## 9. commit して push する

```bash
git add logs/ chronos.md context/
git commit -m "log: YYYY-MM-DD"
```

- `git add` するのは、`logs/`・`chronos.md`・`context/` だけ。ほかの変更を巻き込まないため
- push の前に「push して今日の振り返りを終えますか？」と聞き、「はい」なら `git push` する
- エラーになったら、エラーの文をそのまま見せて、何が起きているか説明する

## 10. 今月の草を見せる

push できたら、`logs/` のファイル名から今月の1行を作って見せ、終わる。今日までの日で、記録した日を ■、記録しなかった日を □、まだ来ていない日を · にする。日数などの数字は添えない。

```
11月 ■■■□■■■□□■■■■■□■■■············
```
